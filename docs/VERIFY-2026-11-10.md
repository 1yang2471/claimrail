## D. ocr 委托模式复审（免 key）

`ocr` 未配 provider key，但 `ocr delegate` 是设计好的免 LLM 路径：`ocr delegate preview
--from 9a215ea --to 75204e6` 给出 21 个可审查文件，`ocr delegate rule <files>` 给出规则组
（死代码 / 空值检查 / 重复逻辑 / 硬编码 / 异步错误处理 / 安全）。按规则逐文件复审后：

- **未用导入**：`node /d/workspace/_tmp/import-audit.mjs src/**/*.mjs bench/*.mjs` 全部 ok
  （上一轮清掉的 15 个没有回流）。
- **发现 1 个真实缺陷（已修）**：`readIncoming` 的 5 秒上限只让定时器赢下 `Promise.race`，
  挂着的 stdin 异步迭代器仍持有事件循环。实测 `spawn` 一个 hook、stdin 不关也不给数据：
  修复前会一直等到 stdin 关闭（宿主那边就是 30s 超时），注释承诺的 5 秒形同虚设。
  修法：超时回调里 `stdin.destroy()`，并给读流 Promise 挂 `.catch`；`readIncoming` 改为可注入
  `stdin` / `timeoutMs` 以便测试。新增两条用例（超时上限、正常流解析），变异：删掉
  `stdin.destroy()` → 超时用例红，还原绿。修复后 CLI 实测 5.2s 退出（原 12s+）。
- **1 处冗余条件（已清）**：`check.mjs` 的 fail-closed 分支里 `!workVisible && ... && git !== 'none'`
  中最后一个条件恒真（`workVisible` 已包含 `none`），删掉并把三元缩进对齐。
- 其余按规则未发现可复现缺陷：`safeResolve` 的越界路径已在 schema 三层 + 运行时兜底；
  `gitToplevel` / `ledgerAbs` / `outAbs` 的空值路径都有降级分支；`RENDER_CHECK_IDS` 与
  `CHECK_IDS` 双写是有意为之（测试钉住），不算重复实现。

测试 394 → 396（新增 2 条），全绿。
