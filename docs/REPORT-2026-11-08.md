# 产品验证报告（2026-11-08）

## 结论

机制层成立：交付前由程序算代价、回访证据、红了拦住，这条链路在测试和活体探针里都跑通了。
这一轮自用协议第一次真的拦住了我自己的交付，并顺着那次拦截抓出两个真 bug。

测量层还不能对外说话：20 个陷阱任务已就位，但真实模型对照没有拿到有效样本。10 步两臂
pilot 的 12 行全部有效，可是协议臂有 5/6 行根本没写台账——门没有机会判。唯一写了台账的
那一行被拦住了，样本只有 1 条。

所以发布文案里的对比数字继续写「尚未测量」。当前数据只支持这一句话。

## 这一轮修掉的真问题

1. **申报无分叉可静默通过**（`24ba3c4`）：`forks: []` 且 diff 落在该类文件面上时，
   `check` 打印审计项、`--json` 给出 `emptyDeclaration`；不拦交付，只让逃逸可统计。
2. **已推送被说成已发布**（`0a85acd`、`5df6f6e`）：判据收窄到远端默认分支与 tag，
   用 `git branch -r --contains HEAD` 覆盖 `git push origin HEAD:main` 这种不设上游的推法；
   默认分支读不出来时返回 `null` → high，不猜。
3. **`verified` 被误当成免检开关**（`24cbbb8`）：文档写明它只是申报，程序不读；
   新增测试钉住「true/false 不改变任何判定」。
4. **副作用扫描误伤**（`88ada07`、`6816cca`）：规则表里的 `rm -rf` 字样和
   `bench/tasks/*/trap.md` 的语料被当成真实动作，把所有分叉升成 high；加豁免并测试钉住。
5. **fan-in 触发的覆写理由冒号后空白**（`88ada07`）：三种 high 来源分开说。
6. **协议臂 CLI 路径写死旧目录**（`88ada07`）：改成从模块位置推导，并加测试断言
   入口真实存在。
7. **夹具预置了「本次刚写」的文件**（`7f4d986`）：`changed-line-precedent` 因此漏拦；
   删除三个预置文件，加不变量测试。
8. **网关 429 把有效运行作废**（`7a526a3`）：指数退避重试，401 不重试；结果增量落盘。
9. **两个陷阱任务没写 `trapRule`**：`empty-declaration` 与 `published-lowball` 的
   `trapRule` 是 `undefined`，旧实现落到 `return true`——任何交付都算踩陷阱。已补规则，
   未知规则改为「不判塌缩」，并加不变量测试逐个检查 20 个任务。
10. **`destructive-lowball` 把「拒绝删除」算成塌缩**：off 臂没有台账，旧规则无条件返回 true。
    已改成看正文是否真的声称删除/清理，明确否认的不算。

第 4、5 条是自用协议的 Stop 钩子拦出来的：它先拦住了一次「先干后证」的交付，顺着
那次拦截才发现扫描和覆写理由的 bug。这是这套东西第一次作用在自己身上，拦对了。

## 没验证到的 / 已知边界

- **真实模型对照没有有效数字**：协议臂 5/6 没写台账，唯一写了台账的样本只有 1 条。
  当前数据不能回答「协议把静默塌缩率降了多少」。
- **模型可能根本不进入协议**：`init` 模板本身能过 `check`，一个无视协议的 agent 仍然
  交付得出去。审计项只在 diff 落在已知文件面上时点名，`refactor` 类故意没有面。
- **`changed-line-precedent` 的 off 臂判定缺口**：规则依赖台账，没台账就不触发。
- **off 臂量不了大多数台账类陷阱**：`stale-render`、`memory-mismatch`、`weak-quote` 等规则
  都要读台账，off 臂按定义没有台账，只能稳定量到「没申报分叉」这一类。off 臂的数字不能
  当成模型对具体陷阱的塌缩率。
- **登录门后的第三方真实产品页未跑**：本地登录门站已验，第三方需要凭据。
- **协议臂 CLI 路径从模块位置推导**：设计选择，没有外部依据，`evidence: null`。
- **429 重试 + 指数退避**：只有本轮 pilot 实测到 429/502 触发后恢复，样本不足，
  `evidence: null`。
- **pilot 三分类口径**：「没写台账不算工具有效」是判断，不是实测结论，`evidence: null`。

## 后续落地（同日）

上面第 1 条建议没有走「换模型/压提示」，而是把缺口本身补上：

- `check` 现在在「工作区有改动 + 台账仍是 init 模板」时退出 1；模板哈希 + 占位理由
  各判一次，init 自己的脚印不算改动。
- Stop hook 记交付指纹（`tree_hash` + `ledger_hash`），沿用旧台账也拦一次；第二次
  放行并追加 `.claimrail/violations.jsonl`（本地，不进 git）。台账被删（初始化过）
  也拦；从没 init 过的仓库仍静默放行。
- 分层：`check` 无状态，管「模板未动」；hook 有状态，管「沿用旧账」。CI 抓不到 stale，
  文档已写明。

测试 367（365 通过 + 2 skip）。新 pilot 用同一组 6 任务跑完（`docs/bench-pilot-2026-11-09.json`，
12 行全部有效）：协议臂 3/6 写了台账，`check` 拦住其中 2 行，1 行放行但撞步数上限；
另外 3 行没做改动就撞了上限。**新门的 `undeclared` 拦截没有被真模型触发**——目前只有
单测证据。off 臂 4/6 交付（2 行算塌缩），协议臂 0/6 交付。发布文案的对比数字仍然是
「尚未测量」：协议臂的零交付有一部分是 10 步预算造成的，申报率要等跑到收尾的运行。

## 建议的下一步

1. 用新门重跑同一组 6 任务，量 `wrote_any` / `declared_fork` / 拦截率；如果模型被拦后
   仍然不写，再换模型或压短提示——先确认门本身有效，再谈模型差异。
2. 把 `changed-line-precedent` 的判定补上正文引用，或者明确标注它只统计 on 臂。
3. 在拿到成对的有效样本之前，README、release note、对外介绍里的对比数字保持
   「尚未测量」。
