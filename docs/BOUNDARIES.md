# 已知的检出边界（别把"未判"当"没问题"）

> 从 AGENTS.md 拆出来：那份文件要在一屏内读完"每条规则由什么拦住"，边界清单是另一件事，
> 长到会把规则表挤到看不见。改边界时改这里。

- `contrast-ok` 曾在磨砂卡片 + 渐变背景上覆盖率极低（真站 7/111），当时只能判"不了"。**v2 已接像素采样**（`src/observe/pixel.mjs` + `png.mjs`，零依赖解 PNG）：
  截图落地后读文字矩形内、字形之外的留白，多点一致才认作背景；点与点不一致（跨渐变）或全落在字形上（比值 <1.05）一律退回未判，不造红也不造绿。
  仍判不了的两类：渐变在采样点之间剧烈变化、以及底色不唯一的地方（**这一类是 2026-11-08 修的**：10px 棋盘背景曾被当成其中一格的颜色报 6.80 合格，而同一处文字压在白格上只有 1.67——那正是它采到的那半边，不是整块）。报告里的 `pixelBackgrounds` 会写明补了几处、几处退回未判。
- 现代色值写法曾经整类漏判（**已修 2026-11-08**）：真站 `iana.org/help/example-domains` 一页 49 处文本里 40 处文字色是 `oklch()`，`parseRgba` 不认识 → 整处不判；更坏的是报告里那句话写的是"采不到实色背景"，照着它去查背景的人永远查不到问题。现在色值统一由浏览器换算（画一个像素读回来）。浏览器自己也认不出的值（`CSS.supports('color', …)` 为假）仍然整处"未判"，不猜。
- 非 git 目录里三个代价输入全部取不到 → 一切按 high。**这是显式的降级模式，不再是静默失明**（2026-11-08）：报告开头写明「非 git 目录（降级模式）…这是保守默认，不是实测结果」，逐条原因写「不在 git 仓库里」，并点名丢掉的是哪一条（repo 档仍读得了文件与行，丢的是先干后证）。另外 git 本身用不了（坏 GIT_DIR / safe.directory）与「不是仓库」分成两种话。
- 测量对象仍然由模型自己填（台账的 `target`）。程序已经挡住了两种最容易被利用的形状：指向不存在的路径或文件里没有的符号 → 判 null（按 high），不再是假零；文件级 fan-in 也要认相对写法。**剩下的残余**：模型仍可以指向一个真实存在、却与本次改动无关的文件，从而拿到一个偏低的 fan-in。这不是 bug 而是协议形状——程序算的是"这个对象"的代价，不是"这次改动"的代价。要根治得让程序自己推导测量对象（例如从 diff 里取被改的文件），那是另一次设计。
- 没有 dev server / 登录态时，SPA 只会得到"五项全未判"，且报告不可引用（0 项绿）。工具不会替你把服务起起来。Shinsekai 真 Vite SPA 已实测：双视口各有触摸目标红（13/12 处），scrollbar/focus 绿，对比度/底部遮挡未判；首次依赖预构建时宽屏 `networkidle` 20 秒超时，预热后重跑成功。绿、红、未判必须分开报告。
- 引文核实只保证**可见正文里有这串字**，不保证那个页面在推荐这个做法。实测 24 个 URL 里有两处命中的是例外条款：W3C 用色页的 "an author cannot use color alone to achieve 3:1 contrast…"、SC 2.5.8 的 "links within paragraphs of text do not need to meet the 24 by 24 css pixels requirements…"。语气程序判不了，台账里的 `url + quote` 就是留给 reviewer 抽查上下文的——这是这一档唯一的人防线，别把它当程序保证。
- "≥3 独立域名推荐同一做法"在数字本身不收敛的主张上不该成立：触摸目标尺寸实测是 24 CSS px（WCAG 2.2 AA）/ 44pt（Apple）/ 48dp（Material）/ 1cm×1cm（NN/g，物理尺寸）。这种分叉该申报的是"各家数字不一致，我选 X 因为 Y"，硬凑"业界都这么做"会被回访戳穿。
- 反爬站回访直接 403（实测 stackoverflow 的问答页）。不伪造浏览器 UA 去绕——这类来源就是不可核实，换静态文档站。补测又见 Medium 系（medium.com、uxdesign.cc）对无浏览器指纹的回访一律 403，`adamsilver.io` 用 undici 直连 fetch failed：**口碑好的 UX 文章有一批永远够不着**，凑不齐 3 域时先检查是不是撞了这类站，而不是急着说"业界不收敛"。
- 分叉型主张（"A 还是 B"）的证据可以引**任一候选方向**的句子，但必须写清支持的是哪个候选；NN/g 谈数据表格的 "unlike with a card-based UI…" 不是支持卡片的票。口味类 4 主张 × 4 域名补测虽有 2/4 通过字串回验，自动筛选混入标题/FAQ 和语义不符的引文，**不等于 2 条主张有三域同向推荐**；强制 precedent 的口味类有效性尚未证实。
- **「本任务没有分叉」有两种形状，只有一种能拦**（2026-11-08 起）：
  - 台账**一字未动**（还是 `init` 模板）而工作区有改动 → `check` 退出 1，交付被拦住。模板哈希与占位理由各判一次，重新序列化也逃不过；`init` 自己的脚印（`.claimrail/`、`AGENTS.md`、`.gitignore`）不算改动。
  - 台账写了 `forks: [] + no_fork_reason` → 算已申报，不拦；若本次 diff 落在该类文件面上，`check` 打印审计项、`--json` 给 `emptyDeclaration`。程序判不了"这里有没有过岔路口"，只让逃逸可统计。
- **沿用旧台账**（写过一次、之后不更新）由 Stop hook 判，`check` 判不了：hook 记上次放行时的 `{tree_hash, ledger_hash}`，工作区变了、台账没变 → 拦一次；第二次仍没申报 → 放行并追加 `.claimrail/violations.jsonl`（本地，不进 git）。这条规则只在 hook 层成立，CI 没有快照，抓不到。威胁模型是「不合作但不攻击」：删快照、改 mtime、伪造证据不在防御范围，删台账会被初始化标记拦住，但不是安全边界。
- **非 git 目录**：没有 diff 就没有「工作区有改动」这个输入，模板规则不启用；其余降级行为见下一条。不要把它说成"门已经检查过"。
- **「已发布」只认默认分支与 tag**（2026-11-08 收窄）：功能分支推上去不算发布。这意味着"推某个分支会触发自动部署"的仓库不在模型里——工具读不到部署策略，不替它猜。默认分支读不出来、且该远端下 main/master 不唯一时返回未知 → high（多问一句，不判低）；这条保守性是有意的。已合并进默认分支的提交仍算发布，`git push origin HEAD:main` 这种不设上游的推法也算——两者靠 `branch -r --contains HEAD` 判，不靠上游。
- **「已发布」只反映本地跟踪引用**：`check` 默认离线，不执行 fetch。别的机器推上去、本地还没 fetch 的提交，可能被判成未发布。这是离线约束，不靠猜补——要更准就让调用方先 fetch，或把发布事实写进 `declared`（目前 CLI 没有这个入口）。
