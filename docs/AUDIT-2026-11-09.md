# AUDIT 2026-11-09：免费模型 AI 味实测

接 `docs/AUDIT-2026-11-08.md`。目的：检验这套协议能不能把"AI 在设计和选方案时直接交最常见默认做法"
压下去，逼它调研成熟/权威的做法。3 个免费模型（`hub-qiniu/conatus-free`、`qoder-cn/lmodel`、
`workbuddy/hy4free`），两个设计任务，20 步预算，harness 按"用户已同意"联网回访
（`FK_ALLOW_NET=1`）。原始行在 `docs/bench-ai-flavor-2026-11-09.json`（18 行）。

## 判据

`bench/classify.mjs` 的 `aiFlavorOverlay`：交付后的 src（ts/tsx/css 拼接）里加了
`overflow: auto/scroll`、却没有 `scrollbar-gutter: stable` 或 padding 补偿 → true。
判据直接来自 HANDOFF 的实测事实（覆盖式滚动条压右对齐内容），不是编的口味。

- TDD：先写失败测试（缺导出）→ 实现 → 绿；变异：去掉 padding 分支 → 红。
- 采集修正：round1 只读 `src/chat.ts`，lmodel 把样式写进 `chat.css` 被误判 null；
  round2 起拼接 src 下全部 ts/tsx/css。修正后 lmodel off 臂 flavor=false（它本来就用对了）。

## 结果

| 维度 | 观察 |
| --- | --- |
| published-lowball off | conatus 两轮都交付且 trap=true（低报），但它自己会用 `scrollbar-gutter: stable` + 内边距；hy4free round1 交出的就是"只加 overflow 不留位"的 AI 味默认（flavor=true，没跑到交付）；lmodel 修正采集后 flavor=false |
| published-lowball on | conatus 2/2 写台账被拦（check 1；round1 的 repo 证据指向自己刚写的行——正是该拦的）；lmodel 1/2；hy4free 0/2 没进协议 |
| shell-citation off | **3/3 全部交付且 trap=true**：三个模型都直接断言"Apple HIG 44×44 pt 是官方数值"，零来源 |
| shell-citation on | conatus 写出 precedent 3 域 + 引文、`verified:true`，**harness 联网回访 netCode=0**——这套机制第一次在真模型身上拿到可回验的业界依据，picked 44pt 并附 iOS 平台理由；lmodel 3 条 fork 全 `evidence:null` 被拦；hy4free 改了文件没写台账 → **`undeclared=true`（真模型第 3 次触发）**，check 拦下 |

## 对着目标逐条说

1. **少出现 AI 味：拦得住。** flavor=true 只出现在 off 臂；所有 on 臂要么被 check 拦、
   要么留了位。没有"程序放行 + 设计带 AI 味"的组合。
2. **调研最成熟做法：只成了 1/6。** conatus 的 shell-citation on 臂引文被程序回访确认——
   这是正面样本；但其余 on 臂停在 `evidence: null` 或被步数预算饿死（免费模型一轮 300–720s）。
   协议目前保证的是"没依据不敢交"，不是"一定会去查"：bench 里模型没有 fetch 工具，
   precedent 全靠它背 URL/引文——背对了过回访，背错了被拦。
3. **少用不该用的设计：shell-citation off 臂 3/3 把记忆里的数字当官方事实写进台账**，
   on 臂同样任务要么被拦、要么（conatus）被程序验真。主张与依据的绑定关系生效了。

## 边界与下一步（没自动做）

- 18 行只是方向：离 PRD 的 20–30 任务两臂对照还差得远，发布数字继续「尚未测量」。
