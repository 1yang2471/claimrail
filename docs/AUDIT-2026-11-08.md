# 设计复核（2026-11-08，第二轮 grill-me）

> 记录这一轮"确认价值与设计合理性"的探针与结论。HANDOFF 只留指针，因为把这一节塞回去
> 会让那份文件超过提交钩子的 20000 字节上限——拆文件是规矩，不是排版偏好。

## 四项活体探针

临时 git 仓库（不在项目内），每项都跑真实的 `node src/cli.mjs check`：

1. **`verified` 字段对判定零作用**：同一台账只把 `verified` 从 `true` 改成 `false`，两次
   `check --json` 输出逐字节相同，都 exit 0。它不是安全洞（证据照样被回验），但会让模型
   误以为写 `verified: true` 有用。
2. **申报无分叉可静默通过**：本次改动新增 `src/page.tsx`（UI 文件），台账写 `forks: []`
   加一句 `no_fork_reason`，`check` exit 0，输出「申报无分叉」——程序没看 diff。
3. **同一改动申报一条分叉**：`evidence: null`、`cost_if_wrong: low`，同样 exit 0，但末尾
   点名「未验证 1 条」。差别只在可见性，不在拦截。
4. **已推送的普通提交**：push `origin/master` 后再跑 `check`，判 `high` 并 block，理由写
   「已发布或有副作用：pushed:HEAD」。代价判 high 是保守设计，可以接受；问题是措辞把
   "已推送"说成"已发布"，会让人去查错方向。

## 这一轮落地了什么

## 随后落地：published 收窄（同日）

用户选了"两者都做"。第一版按"当前分支上游是不是默认分支"写，探针立刻抓到一个假低：
`git push origin HEAD:main` 不设置上游，旧写法会把"已经在默认分支上"判成未发布。
改成直接问 git"哪些远端分支包含 HEAD"（`branch -r --contains HEAD`）——这一步同时覆盖
功能分支、已合并、本地领先三种形状，也不漏不设上游的推法。默认分支优先读 `<remote>/HEAD`，
读不到只认该远端下唯一一个 main/master，两个都在或都没有 → `null` → high。
理由句改成「已推送/已发布或有副作用」，并带上游名（`pushed:origin/main`）。

测试 325 → 335；六条变异（去掉默认分支成员判断 → 红 1、未知退回 false → 红 2、
去掉 main/master 兜底 → 红 3、去掉 `--contains` → 红 2、理由句退回 → 红 1、
去掉上游名标签 → 红 1）全部红→绿。

## 真模型首跑：6 步预算无效（2026-11-08）

作废，13 行有效，其中只有 1 行自然结束**（`null-report`，交付且正确指出两项 `ok: null`

## 同日落地：未申报本身也拦住交付

pilot 暴露的缺口不是模型不听话，而是门只校验"已申报"的东西：`check` 在台账仍是 init
模板时退出 0，`hook` 在没有台账时静默放行。用户拍板把「没申报」升级成阻断，拆成两层：

- **check（无状态）**：工作区有改动、台账仍是 init 模板 → 退出 1。模板指纹存在
  `.claimrail/template.sha256`；老仓库没有指纹时退回当前模板常量；占位理由单独判，
  重新序列化也逃不过。init 自己的脚印（`.claimrail/`、`AGENTS.md`、`.gitignore`）不算改动。
- **hook（有状态）**：记上次放行时的 `{tree_hash, ledger_hash}`；工作区变了、台账没变 →
  拦一次；第二次仍没申报 → 放行并追加 `.claimrail/violations.jsonl`（本地，不进 git）。
  台账被删（初始化过）也拦；从没 init 过的仓库仍静默放行。
- **分层原因**：`check` 若在通过时更新快照，agent 反复跑 check 就能把快照推着走；
  CI 里没有 hook 快照，所以 stale 规则只在宿主层成立。

测试 360 → 367；六组变异（模板判定、占位理由、init 脚印、stale、违规记录、删台账）
全部红→绿。`check.mjs` 因 20KB 钩子拆出 `src/undeclared.mjs`、`src/commands/hook.mjs`、
`src/delivery.mjs`。新 pilot 用同一组 6 任务重跑，量的是「被拦后有没有写台账」而不是
off/on 塌缩率。
