> 会让那份文件超过提交钩子的 20000 字节上限——拆文件是规矩，不是排版偏好。

## 四项活体探针

临时 git 仓库（不在项目内），每项都跑真实的 `node src/cli.mjs check`：

1. **`verified` 字段对判定零作用**：同一台账只把 `verified` 从 `true` 改成 `false`，两次
   `check --json` 输出逐字节相同，都 exit 0。它不是安全洞（证据照样被回验），但会让模型
   误以为写 `verified: true` 有用。
2. **申报无分叉可静默通过**：本次改动新增 `src/page.tsx`（UI 文件），台账写 `forks: []`
   加一句 `no_fork_reason`，`check` exit 0，输出「申报无分叉」——程序没看 diff。
3. **同一改动申报一条分叉**：`evidence: null`、`cost_if_wrong: low`，同样 exit 0，但末尾
   点名「未验证 1 条」。差别只在可见性，不在拦截。
4. **已推送的普通提交**：push `origin/master` 后再跑 `check`，判 `high` 并 block，理由写
   「已发布或有副作用：pushed:HEAD」。代价判 high 是保守设计，可以接受；问题是措辞把
   "已推送"说成"已发布"，会让人去查错方向。

## 这一轮落地了什么

按用户决定只动第 2 项：新增 `src/audit.mjs` + `src/commands/check.mjs` 的审计项。
`forks: []` 且本次 diff 落在该类文件面上时，文本视图打印审计项、`--json` 给出
`emptyDeclaration`（`touched` / `touchedTotal` / `reason`），**不参与 action 与退出码**。

面分类：`ui-new` 认 tsx/jsx/vue/svelte/astro/html/css/scss/sass/less；`docs-new` 认
docs/ 路径与 md/mdx/rst；`api-design` 认 api/routes/controllers 路径、openapi/swagger
文件名与 proto/graphql。`refactor` 故意没有面——它的面是任意代码，命中等于没有区分度。

测试 318 → 325；四条变异（关掉计算 → 红 4、去掉面过滤 → 红 6、去掉上屏 → 红 4、
去掉 `no_fork_reason` → 红 1）全部"改坏→红、还原→绿"，还原后哈希逐字节一致。

## 随后落地：published 收窄（同日）

用户选了"两者都做"：`headOnRemoteDefault` 只认远端默认分支（包括已合并进去的提交，
用 `merge-base --is-ancestor` 判）与 tag；功能分支已推送不再算发布；默认分支读不出来时
只认 main/master 且上游同名，其余 `null` → high。理由句改成「已推送/已发布或有副作用」，
并带上游名（`pushed:origin/main`）。

测试 325 → 333；五条变异（退回"任何推送" → 红 3、去掉 main/master 兜底 → 红 2、
去掉合并判定 → 红 1、理由句退回 → 红 1、去掉上游名标签 → 红 1）全部红→绿。
