# claimrail 全方位评估（2026-11-13）

回答一个问题："**该项目会不会太麻烦、约束性太强，从而限制 agent？**"
方法：rederive 式重推（每道约束回到光秃秃的问题——没有它什么事会坏）× tidy 式减法（负担里哪些是必须、哪些是赘余）× 全实测。不给印象分，每条判定挂数据。

## 0. 光秃秃的问题

规格没写完时，AI 必须输出点什么，于是它输出它见过最多的那个做法；岔路口被走掉，且没有任何地方记录"这里曾有岔路口"；用户只能在实物做完后用一句"感觉不对"去描述一个已不可逆的决定。

反事实（如果整套机制删掉会怎样）：bench 20×2 实测，off 臂（普通提示）交付 12/20，其中**静默塌缩 4/12——照默认交差且不自曝**。这就是没有 claimrail 时的基线。

## 2. 负担实测账本（分受众）

**agent 付的：**
- 每仓库一次 `init`（1 条命令）；
- 每会话读协议：SKILL.md **18,580 字节 / 260 行**，中文 5,278 字符（≈5.3k tokens），双语全读 ≈7k tokens——**这是最大的单笔认知成本**；
- 写台账：真实增量小（跨日累积），JSON 单行、≤120 字符；
- `check` 0.8 秒；
- 被打断：bench median 0（n=18）；真实使用 0 次。

**用户付的：**
- review 台账（40 条是跨日累积，非单任务）；
- 回答被拦的问题：一般仓库 median 0；永雏小菲型仓库（40 分叉、离线 precedent 全部回验失败）**每次交付 37 问**——真实使用里最重的一档。

**agent 不付的：** 419 项测试、变异验证文化、bench 基建——全是维护者（本会话）的负担，不落在使用它的 agent 头上。

## 3. "太麻烦/约束太强"的三问三答

**① 会限制 agent 完成工作吗？**
紧预算下会：协议臂 11/20 撞 20 步上限、交付 6/20 vs off 臂 12/20。但注意两点：(a) 撞上限那 11 次的申报分叉只有 **0–2 条**——重的不是写台账，是"停下来取证/问人"取代了"直接交差"；(b) off 臂自己也撞 8/20（这个模型在这些陷阱任务上本来就容易撞顶）。**正常预算下未测**——真实使用中三个仓库的交付都在正常发生，零 violations、快照在推进。

**② 会剥夺 agent 能力吗？**
不剥夺，只改签名方式：所有"悄悄选"变成"明着选"。且设计上有完整的逃逸口清单（这是"约束太强"指控的最好反证）：`typo`/`rename`/`bugfix-known-cause` 三类不走协议、`forks: []`+理由合法、check 最多跑两次（第二次仍拦就停下问人，不许硬磨）、钩子只拦一次（`stop_hook_active` 防死循环）、未 init 的仓库静默放行、`--unattended` 转 halt、低代价无证据放行但点名、规则四让逃逸可统计。**每一条硬约束都带计数器，没有死锁设计。**真实使用六天 0 拦截、0 violations、钩子崩溃时宿主 fail-open——不存在"卡死 agent"的实测案例。

**③ 会让 agent 变笨吗？**
认知成本集中在协议阅读（≈5.3k tokens 中文 / 7k 双语）与"取证/问人"的步数，不在运行时。台账单行 120 字限制反而防了"800 字台账没人读"的复杂化。

## 5. 判定

**"约束性太强限制 agent"不成立，"有点麻烦"成立且价格可接受。**机制设计上没有一道硬约束不带逃逸口和计数器，不存在锁死 agent 的形状；真实使用六天 0 拦截、0 violations；紧预算下用交付率换诚实率的代价（6/20 vs 12/20）是真实存在的，但那是"停下来取证/问人"的成本，不是"填表"的成本——而换来的是塌缩 4/12 → 0/6。

三个诚实警告：
1. **规则三（防塌缩）刚协议层武装，真实效果未测**——它是 R3 的核心武器，第一次真实触发之前，"防熟悉偏好"这条腿只有 bench 证据；
2. **紧预算场景未测**（真实宿主无 20 步上限，但长会话同样有预算压力）；
3. **"真实拦截→续轮→改正"的闭环还没有第一例实地证据**（0 violations），防御价值目前靠 bench + 真实合规支撑。

## 6. 如果要做，下一步按性价比

1. **S1 SKILL 瘦身/双语拆分**（约 7k→3.5-4k tokens/会话）——最大单项减负，需要真机回归触发率；
2. 等第一次真实拦截发生（violations.jsonl 第一条记录），复盘续轮行为——补上防御价值闭环的最后一块实证；
3. 规则三第一次真实触发后复盘（永雏小菲补申报时最可能）。

**不做**：收紧门语义（会加剧 37 问风暴）、schema 强制 target、删历史证据链、动 AGENTS.md 结构。
